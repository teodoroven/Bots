## Архитектура

- `main.py` - тонкая точка входа из корня проекта. Делегирует запуск в `relay.bootstrap`
  и экспортирует публичную совместимость через `relay.public`.
- `relay/` - app-layer: обработчики, сессии, доменная логика, GPT, очереди,
  уведомления, runtime-миксины и публичные app-level exports.
- `bots/` - transport-layer: Telegram/VK-адаптеры, базовые абстракции,
  wrapper-сообщения, клавиатуры, вложения, runtime для транспортов.
- `db/` - storage-layer: SQLAlchemy-модели, репозитории, storage API,
  настройки сессий и Alembic-миграции.
- `json/` - публичные команды и локализация.
- `docs/` - проектная документация.
- `tests/` - публичный `unittest`-набор для архитектуры, storage и транспортов.

## Границы слоёв

- `main.py` должен оставаться тонким entrypoint. Не переносите туда handlers,
  session-логику, storage-логику или transport-specific код.
- `relay` работает через абстракции `bots`, wrapper-сообщения и публичные transport API,
  а не напрямую через детали Telegram/VK SDK.
- `relay` содержит app/domain/runtime-логику: автошкола, сессии, очереди,
  уведомления, GPT-сценарии и координация storage.
- `bots` не должен содержать бизнес-логику автошколы, GPT-логику,
  SQLAlchemy-модели или репозитории.
- `db` остаётся слоем хранения. Не добавляйте туда session/handler-логику app-layer,
  Telegram/VK API-вызовы или GPT-вызовы.
- Compatibility alias допустимы только для сохранения существующих импортов и тестов.
  Не расширяйте их как новый основной API без необходимости.

## Runtime-правила

- Не менять семантику `run_bot()`, если задача прямо этого не требует.
- Отсутствие bot config должно оставаться ошибкой для реального запуска.
- Infrastructure checks и CI не должны запускать Telegram/VK polling.
- Не скрывать реальные ошибки широкими `except`, если задача не про error handling.

## Storage-правила

- Проект использует SQL storage через SQLAlchemy и Alembic.
- SQLite должен оставаться рабочим для локальных проверок и CI.
- PostgreSQL используется для Docker/server-сценариев.
- Alembic-миграции должны соответствовать ORM-моделям.
- Storage API должен изолировать app-layer от деталей SQLAlchemy, насколько это уже
  предусмотрено текущей архитектурой.

## Безопасность

- Правила безопасности, секретов, runtime-данных и публикации репозитория описаны в `SECURITY.md`.
- Не дублируйте security policy в `AGENTS.md`; при изменениях конфигурации, Docker,
  storage, тестов или CI сверяйтесь с `SECURITY.md`.

## Стиль Python-кода

- Целевая версия - Python 3.12.
- Для новых или изменённых публичных функций и методов используйте type hints.
- Используйте `list[...]`, `dict[...]`, `tuple[...]`, а не `typing.List`,
  `typing.Dict`, `typing.Tuple`.
- Предпочитайте union через `A | B`.
- Сохраняйте существующий стиль пробелов в вызовах: `call(arg = value)`.
- Не превращайте изменения в общий style-only refactor без прямой задачи.
- Тесты пишутся на `unittest`.
- Тестовые файлы называются `*_test.py`.

## Документация

- Module docstring должен описывать назначение модуля, архитектурный слой и только
  top-level публичные классы/функции.
- В module docstring не перечисляйте методы классов.
- Class/method docstring должен описывать реальное поведение и side effects:
  запись в БД, отправку сообщений, изменение очередей, вызовы внешних API.
- Не используйте автогенерированные фразы и шаблонные описания без смысла для проекта.
- Не выдумывайте поведение, которого нет в коде.
- Не требуйте отдельные `:type` blocks. Типы должны быть видны из сигнатур.
- В тексте docstring можно упоминать типы через обратные кавычки, если это помогает.
- Не создавайте противоречие между правилами типов и docstring: сигнатура - источник
  правды для типов, docstring - для назначения, эффектов и ограничений.

## GitHub Actions

- Production CI находится в `.github/workflows/ci.yml`.
- CI должен проверять установку зависимостей, компиляцию, import sanity check,
  Alembic-миграции и `unittest`.
- CI использует Python 3.12.
- Не добавляйте `continue-on-error: true`.
- Не добавляйте фиктивные successful steps, placeholder checks или проверки,
  которые ничего не валидируют.
